## 总体判断

**这次升级没有出现“全面崩”**：9 个扩展在 pi 1.4.0 下逐个加载全部通过，9 个一起加载也通过（含内建 `codemode` / `mcp`），主题能被 1.4.0 正常加载，skills 的 Pi 冒烟测试通过；升级后先测到 1276 个 vitest 用例全过，PR-2 新增 1 条回归后为 1277。

**升级后、PR-1/PR-2 之前，仓库门禁是红的**：biome 通过，`tsc` 报 **106 个错误**，归因只有 **4 处**；其中 1 处是**真实运行时回归**，不是类型噪音：

- pi 1.2.0 起，`before_agent_start` 变成按 `messageType` 判别的联合类型；`pi.sendMessage(..., { triggerTurn: true })` 触发的运行不再带 `prompt`。Telegram 扩展仍直接读 `event.prompt.trimStart()`，在“计划执行”这类自定义触发运行里会抛 `TypeError`（已复现，PR-1 已修）。
- 其余缺口集中在：`typebox` 依赖归属、Node 引擎下限、模型目录刷新未 `await`、测试替身未跟上 `ExtensionToolContext`、主题元数据、全屏模式的手工验证。

**结论：不需要重写 provider、会话或渲染架构。** `yoki-newapi` 的 provider 注册在 1.4.0 下仍然兼容；`yoki-ui`、`yoki-plan`、`yoki-ask-user-question` 的核心交互也没有被移除的 API。PR-1/PR-2/PR-3 已完成；剩余按 PR-4…PR-6 收口（另有 1 个可选增强 PR）。
